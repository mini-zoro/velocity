# Spec: `.sublime-theme` engine + our default theme, and the minihtml engine

Status: P3 / lane B (engines, headless). Locations: new `crates/vel-theme/`, new `crates/vel-minihtml/`,
our default theme in `crates/velocity/resources/Packages/Theme - Velocity/` (lane B owns that directory).

References (public docs only): https://www.sublimetext.com/docs/themes.html (format, terminology,
inheritance, variables, colors, font sizes, attributes, settings, properties, elements, file icon
themes, customization) and https://www.sublimetext.com/docs/minihtml.html (tags, attributes,
protocols, inline formatting, predefined classes, CSS units/colors/variables). Clean-room: do not
copy the Default/Adaptive themes or their textures; design our own.

## 1. `vel-theme` — rule engine (no rendering)

- Load `.sublime-theme` JSON (lenient: comments, trailing commas) with `variables`, `extends`
  (theme inheritance), `rules`; user override files merged like Sublime (User/<Theme>.sublime-theme
  appends rules).
- Rule matching exactly as documented: `class` (space-separated multi-class, all must be present),
  `attributes` (incl. `!attr` negation), `settings` (array of booleans incl. `!setting`, or object
  with string/array values), `parents` (ordered furthest→closest, each with class/attributes),
  `platforms`. Later rules override earlier ones per property.
- Property model: all documented properties typed (layers `layer0..layer3.{tint, opacity, texture,
  inner_margin, draw_center, repeat, tint_modifier}`, `content_margin`, `fg`, `bg`, `font.*`,
  `shadow_*`, `color_scheme_tint`, `indent`, `row_padding`, `icon_*`, `hit_test_level`, element
  specific properties…), colors in theme color syntax (incl. `color()` mods shared with
  `vel-color-scheme` if feasible), font sizes (`font.size` absolute and relative), and
  **animations** (`*.opacity` / `tint` transitions with `{target, speed, interpolation}`).
- Element registry: the documented element classes (`title_bar`, `tabset_control`, `tab_control`,
  `tab_label`, `tab_close_button`, `sidebar_tree`, `tree_row`, `sidebar_label`, `quick_panel`,
  `quick_panel_row`, `quick_panel_label`, `overlay_control`, `popup_control`, `auto_complete`,
  `status_bar`, `panel_control`, `scroll_bar_control`, `minimap_control`, `text_line_control`,
  `button_control`, `icon_button_control`, `label_control`, `kind_container`, `sheet_contents`,
  `grid_layout`, …) with their attributes; an API
  `resolve(&ElementPath /* chain of (class, attributes) */, &Settings, Platform) -> ResolvedStyle`
  that lane A's widgets call every frame — cache by (path hash, settings revision); hot path
  allocation-free.
- Textures: PNG loading (with @2x/@3x variants), 9-patch metadata from `inner_margin`; provide
  decoded RGBA + metadata for the renderer (lane A uploads them).
- File icon themes (ST4 build 4213): `.sublime-file-icons` JSON mapping, resolve icon for a path.
- Tests: a corpus of rule-matching cases built from the documentation examples; property tests for
  "later rule wins" and parents ordering; loading a few popular third-party themes from their
  public repos **only as test fixtures fetched at test time or skipped if offline** (don't vendor
  them): measure that they parse.

## 2. Our default theme: "Velocity"

- Design an original theme (dark + light variants following the OS appearance, matching the Velocity
  Dark/Light color schemes), drawn mostly with tints/fills (few textures; any textures must be our
  own PNGs generated by a script in the repo), covering every element in the registry. Include a
  short design doc (spacing scale, radii, typography, states).

## 3. `vel-minihtml` — HTML/CSS subset engine (layout only, no GPU)

- Parse the documented tag set (`html, head, style, body, h1–h6, div, p, ul, ol, li, b, strong, i, em,
  u, big, small, a, code, var, tt, span, br, img`) and attributes (`class`, `id`, `style`, `href`,
  `title`), the documented CSS subset (selectors: type, class, id, descendant, child, multiple;
  properties listed in the doc — display block/inline/inline-block/list-item/none, margin, padding,
  border(-radius), width/height/min/max, color, background-color, font-family/size/weight/style,
  line-height, text-decoration, white-space, text-align, vertical-align …; units px/em/rem/%;
  colors incl. `color()` mods; CSS variables `var(--x)` with the predefined variables from the color
  scheme, e.g. `--background`, `--foreground`, `--redish` …; predefined classes), and protocols
  (`subl:` command URLs, `http(s):`), plus inline formatting as documented.
- Layout to a display list (boxes, text runs with styles, images, link hit regions, tooltips)
  given a font metrics provider trait and a max width; text shaping delegated to the caller via
  the trait. Wrap, inline-block, lists with bullets/numbers, borders/radius, scroll height.
- Budgets: layout of a typical LSP hover popup (≈2 KB HTML) ≤ 0.5 ms; 200 annotations ≤ 5 ms.
- Tests: golden display lists for documentation-style snippets.
