# 图形化设置界面（Settings UI）方案

> 2026-11-20。基于 main `e163180` 的代码与现有设置体系。目标：在不破坏 Sublime 兼容性的前提下，给 Velocity 一个可搜索、按控件编辑的设置页，所有改动写回 User 的 `Preferences.sublime-settings`，立即生效，可撤销。

## 1. 定位与原则

1. **数据只有一个来源。** 页面上不新增任何「只在界面里存在」的设置。每一项都来自随包默认 `Packages/Default/Preferences.sublime-settings`，外加一份我们自写的界面元数据（分组、控件类型、取值范围、别名、何时生效）。写回仍是 User 里的同名 JSON 键，Sublime 或手改 JSON 都看得懂。
2. **保留 Sublime 的 JSON 入口。** ⌘, 打开 Default/User 双栏 JSON 编辑器。图形化设置页另有菜单与命令面板入口，并提供「在 JSON 中编辑」按钮。
3. **只编辑用户级、通用的设置。** 平台专用（`Preferences (OSX)`）、语法专用、按键等第一版只显示来源与值，附「以 JSON 编辑」；不做图形编辑。
4. **写入安全优先。** 复用现有 `set_user_preference`：原子写、保留注释与其他键。User 文件无法解析时进入只读并给出提示，绝不覆盖坏文件。

## 2. 界面结构

单窗口，单栏（不再用 Sublime 的双栏），窗口标题「设置」（英文 Settings）。

```
┌────────────────────────────────────────────────────────────────────┐
│ [搜索：设置名称、说明、别名]          [只看已修改]  [全部撤销]       │
├──────────────┬─────────────────────────────────────────────────────┤
│ 编辑          │ 编辑                                                  │
│ 外观          │  自动换行                 word_wrap      [开关]   ✕  │
│ 字体与行      │  以空格代替制表符         translate_tabs… [开关]  ✕  │
│ 文件与编码    │  制表符宽度               tab_size        [4]   ✕  │
│ 查找          │  …                                                    │
│ 侧栏与索引    │      说明文字（一行，悬停/展开看完整说明）             │
│ 构建          │      生效时机：立即 / 新窗口 / 下次保存   在 JSON 中编辑│
│ 包与主题      │                                                        │
│ 语言          │ 外观                                                  │
│ 开发者        │  …                                                    │
└──────────────┴─────────────────────────────────────────────────────┘
  已修改 3 项 · 用户设置：~/Library/Application Support/Velocity/Packages/User/Preferences.sublime-settings
```

- **左栏：** 分类，每个分类后显示已修改项数。分类只出现在有该分类设置时。
- **顶栏：** 搜索（按设置名、英文键、英文说明、中文说明、别名匹配；中英两种查询都能命中）；「只看已修改」开关；「全部撤销」。
- **行：** 名称（本地化）+ 英文键名（等宽小字）+ 控件 + 修改标记 + 单项复位（✕）；下方显示一行独立编写的本地化说明，末尾显示生效时机与「在 JSON 中编辑」链接。枚举菜单打开时隐藏该行的链接。
- **底栏：** 已修改项数、User 文件路径；文件有语法错误时这里变成错误提示，页面只读。
- **打开方式：** 偏好设置 › 图形化设置…（`Settings (Graphical)…`）或命令面板「偏好设置：图形化设置」（`Preferences: Settings (Graphical)`）在当前窗口打开设置页。可从双栏 JSON 窗口使用同一条命令。⌘,、Velocity › 设置…、偏好设置 › 设置…和命令面板「偏好设置：设置」打开双栏 JSON 编辑器。

## 3. 控件映射

| 类型 | 判定 | 控件 |
| --- | --- | --- |
| 布尔 | 默认值是 true/false | 开关（空格/回车切换） |
| 枚举 | 元数据里列出取值集合（如 `word_wrap`: auto/fixed/false，`draw_white_space`，`file_tab_style`，`overlay_scroll_bars`，`ui_language`） | 下拉；允许旧式布尔写法的项（`word_wrap`、`hot_exit` 等）下拉里额外给 true/false |
| 数字 | 默认值是数字，元数据给出范围/步进 | 输入框 + 步进（`font_size`、`tab_size`、`wrap_width`、`scroll_speed`…） |
| 字符串 | 默认值是字符串且非枚举 | 输入框，实时校验（如 `word_separators`、`sub_word_separators` 只做合法性检查） |
| 字符串数组 | 默认值是数组（`rulers`、文件列表、`ignored_packages`） | 标签编辑器：逐项输入，回车添加，✕ 删除 |
| 颜色 | 键名以 `color` 结尾或元数据标注 | 色块 + 十六进制输入（第一版先给文本输入 + 预览色块） |
| 复杂对象 | `new_window_settings`、`build_env`、`dictionary` 之外的 object | 只读摘要 + 「以 JSON 编辑」 |
| 只读/无效果 | 文档标为「仅为兼容保留」 | 灰显，说明原因 |

- **生效时机**（立即 / 新窗口 / 下次打开文档 / 下次保存 / 下次构建）：来自设置参考的数据，直接显示在行尾；需要新窗口的给一个「新建窗口」按钮。
- **连带影响**：例如改 `translate_tabs_to_spaces` 会改变制表符相关设置的可见性；把 `word_wrap` 设为固定宽度时显示 `wrap_width` 行。用元数据里的 `show_when` 表达，不写死在代码里。

## 4. 元数据

新增 `Packages/Default/settings-ui.json`（JSONC，自写、可注释），每项：

```jsonc
{
  "group": "editing",                 // 分类 id
  "control": "enum",                  // bool | enum | number | text | array | color | json_only
  "choices": ["auto", "fixed", "false"],
  "range": [1, 72], "step": 1,        // number
  "show_when": { "word_wrap": "fixed" },
  "aliases": ["自动换行", "wrap"],     // 搜索别名，中英都有
  "name": "…",                         // 英文显示名称
  "description": "…"                   // 独立编写的英文单行说明
}
```

- 生成与校验：`scripts/settings-reference.py` 扩展为同时生成元数据骨架并校验——**每个随包键恰好一条元数据、没有多余条目、控件类型与默认值类型兼容**，否则测试失败。分组与控件类型由我们人工确定（一次），不靠猜。
- 所有设置的中文名称与说明均收录在 `zh-Hans.sublime-localization`。无论当前界面语言是什么，都可用中英文搜索。键名、资源名、编码、语法名不翻译。引用和网址只放在设置参考的备注列，不从默认文件注释生成界面说明。

## 5. 写入、撤销与冲突

- **写入：** 每次改动调用现有的 `set_user_preference(key, value)`（`workbench.rs:183`）：内存层立即生效、进 `track_settings_write`、后台原子写 User 文件，保留注释。连续拖动数字框时合并成一次写。
- **复位：** 单项复位 = 从 User 文件删除该键（`Document::remove`），回到默认值。
- **撤销：** 页面内的 ⌘Z 依次撤销本页做过的修改（把上一个值写回）；「全部撤销」把 User 文件恢复到打开页面时的快照，**仅当文件之后没有被外部修改**时才可用，否则提示「文件已在外部被修改」。
- **外部修改：** 页面跟随设置修订号刷新；User 文件被外部改坏（无法解析）时整页只读，底栏显示「第 N 行：…」，并给「以 JSON 修正」按钮。
- **不写非法值：** 输入框校验不通过时不写、不弹窗，行内红字说明。

## 6. 渲染与交互

- **实现形态：** 一个新的视图类型（类似图片视图/输出视图那样整窗自绘），复用现有面板绘制原语（行、文字、图标、输入框、弹窗），不用命令面板模拟。约 200 行，不需要虚拟列表；如需可只画可见行。
- **键盘优先：** 上下移动、空格切换、回车编辑、Tab 在搜索与控件间移动、Esc 逐级返回（编辑→行→分类→关闭）。搜索框自动获得焦点。
- **无障碍：** 每行暴露名称、键名、当前值、说明与「已修改」状态；切换开关时朗读「自动换行，已关闭」。分类可作为列表的组标题。
- **性能：** 页面构建一次（约 200 行），只在设置修订号变化时重建；开关切换只重画一行。目标：页面帧时间与命令面板同量级（≤ 1 ms CPU/帧），不影响 `--headless-view-features` 指令数（≤ +1%）。
- **渲染场景：** 新增 `settings_ui` 场景（中/英、深/浅、1x/2x、搜索有结果、只看已修改、JSON 不可解析的只读态），交设计代理复核。

## 7. 兼容性

- ⌘, 和应用菜单的「设置…」继续用 `edit_settings` 打开双栏 JSON。偏好设置菜单和命令面板也保留 Sublime 用户熟悉的「设置」名称，另用「图形化设置」标明 Velocity 新增页面。
- `ui_language` 默认是 `"auto"`：按 macOS 偏好语言顺序选用第一个受支持的语言，否则使用英语。
- 第三方包自己的设置、语法设置、按键映射：第一版不做图形编辑，页面里给入口（打开对应 JSON）。
- 不新增设置键；页面的偏好（如上次停留的分类）只放在会话里，不写 User 文件。

## 8. 分阶段

1. **R1 骨架**：元数据生成与校验、设置页（分类、搜索、布尔/数字/文本三种控件、写入、单项复位、只看已修改）、英文界面与 JSON 入口。测试：每键可被搜索到并正确编辑、写入后立即生效、复位、User 文件保留注释、坏文件只读。
2. **R2 控件与安全**：枚举/数组/颜色控件、`show_when` 连带显示、撤销与全部撤销、外部修改与坏文件处理、键盘与无障碍。
3. **R3 中文与外观**：所有设置的名称及说明译为简体中文，复核深浅色与不同缩放的渲染场景；按 D1 恢复 ⌘, 的 JSON 入口，按 D2 默认跟随系统语言。
4. **R4 收尾**：文档（`docs/settings.md` 每行链到设置页的定位）、MANUAL_TEST 更新、与既有 settings-effect 扫查测试联动（每行带「测试」链接，指向覆盖它的测试）。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 设置页与手改 JSON 同时改，后写覆盖 | 写入走同一 `set_user_preference`；页面监听修订号刷新；冲突时以磁盘为准并刷新页面 |
| 元数据与默认文件漂移 | 生成脚本 + 双向校验测试（每个键恰好一条、无反查失败） |
| 枚举取值靠猜 | 取值集合人工确定并注释来源（公开文档 + 默认文件注释）；旧式类型允许自由输入 |
| 说明或翻译遗漏 | 每个设置必须有名称和单行说明；随包语言目录必须覆盖每条设置文案 |
| 页面性能 | 一次性构建、按修订号重建、只重画变化行；纳入指令数对比 |
| 与 Sublime 习惯冲突 | 保留 ⌘, 和「设置」的 JSON 入口；给图形化设置单独命名 |

## 10. 验收标准

- 任一随包通用设置都能在搜索或两次点击内找到，并用正确的控件编辑；改动立即生效（既有 184 项 settings-effect 扫查可复用为证据）。
- 复位、撤销、全部撤销都可用；User 文件注释与无关键在编辑后逐字节保留。
- User 文件损坏时页面只读、不覆盖，并能一键转去 JSON 修正。
- 中文界面完整（名称、说明、分类、错误提示）；中英文查询均可用。
- 键盘可完成全流程；VoiceOver 能读出名称、键名、值与状态。
- gate 全绿，指令数变化 ≤ 1%；新增渲染场景供设计复核。

## 11. 可行性分析（2026-11-20，基于 main `e163180`）

**结论：可行，按第 8 节分 4 轮开发。**预计 R1、R2 各 1–2 轮 codex，R3 一轮（含设计复核），R4 半轮。第一版只做随包的通用设置，与方案一致。

### 已有基础，可以直接复用
| 方案依赖 | 现状 |
| --- | --- |
| 写回 User 文件 | `Workspace::set_user_preference`（`workbench.rs:183`）：内存层立即生效、清掉各标签页的 View 层覆盖、后台原子写、保留注释、`track_settings_write` 可追踪失败 |
| 键的清单、默认值、读取点、生效时机 | `docs/settings.md` 由 `crates/velocity/scripts/settings-reference.py` 生成；第 26 轮起每个随包键要么有读取点，要么注明「仅为兼容保留」，否则测试失败；还给出了「新窗口 / 下次打开 / 下次保存 / 下次构建」等生效时机 |
| 生效证据 | `settings_effect_tests`：184 个有读取点的键逐项修改，确认画面或操作有变化，可直接作为验收证据 |
| 中文 | `vel-i18n` 加 `zh-Hans.sublime-localization`，含目录完整性、占位符一致性和绘制文字审计测试 |
| 绘制和输入 | 面板绘制原语（行、文字、徽标、输入框、弹窗）、`vel-ui` 输入框（支持输入法）、整窗自绘视图的先例（图片视图、输出视图） |
| 无障碍 | `app_a11y.rs` 的无障碍模型（`Role`、`Node`、`Region`），由原生适配层按需查询 |
| 渲染复核 | `--render-scenes` 支持 `--language` 与深浅色，并有设计代理流程 |

### 需要新做的
1. **`Document::remove(key)`**：`vel-config/src/json.rs` 目前只有 `set`、`append_array`、`remove_array_element`，单项复位需要删键时保留注释与格式。工作量小。
2. **设置页视图**：新的工作区页类型（与图片视图同级），包括分类栏、搜索框、行列表和底栏。约 250 个随包键，一次构建即可，不需要虚拟列表。
3. **控件**：开关、下拉、数字步进、文本框（复用输入框）、标签编辑器、色块。下拉可复用快速面板的弹出层，标签编辑器是新控件。
4. **元数据** `Packages/Default/settings-ui.json` 及其生成和校验：分组和控件类型需要人工定一次，脚本负责双向校验。
5. **撤销栈与「全部撤销」的快照比对**：用设置修订号和 User 文件的磁盘戳判断文件是否在外部被改过。
6. **无障碍角色**：开关、弹出按钮、文本框、分组标题在 `Role` 里要有对应项。缺的话要扩展原生适配层，需在真实窗口里用 VoiceOver 验证。

### 风险与调整建议
- **⌘, 的兼容性（D1）**：恢复 Sublime 的双栏 JSON 入口，设置页使用单独命名的菜单与命令面板条目；两种界面可互相打开。
- **和 i18n 框架改造的先后**：通用 i18n 改造（按语言标签自动发现目录）和设置页的中文（R3）都会改目录与语言菜单。安排上先做 i18n 改造，或让 R1 的所有界面文字一开始就走 `tr`，避免二次返工。
- **连续写入**：每次改动都会排一次后台写。数字框拖动或连续输入要合并（方案已写），并沿用 `discard_settings_write` 处理写入失败。
- **值的类型**：部分键接受旧式写法（`word_wrap`、`hot_exit` 等可以是布尔也可以是字符串）。`settings.rs` 的 `retain_valid` 已有允许类型表，控件和校验以它为准，不另写一套。
- **性能**：设置页只在打开时构建，按修订号重建，不进编辑器帧路径。纳入指令数对比即可。

### 开发安排
- R1：`Document::remove`、元数据骨架与校验、设置页骨架（分类、搜索、开关、数字、文本、单项复位、只看已修改）、图形与 JSON 入口、英文完整。所有文字走 `tr`。
- R2：下拉、标签编辑器、色块、`show_when`、撤销与全部撤销、外部修改与坏文件只读、键盘操作、无障碍。
- R3：中文分类名、设置名与说明、渲染场景与设计复核，落实 D1 和 D2。
- R4：文档链接、MANUAL_TEST、与 settings-effect 测试联动。
