## 1. App bundle and distribution artifacts (no publishing)

- A reproducible `scripts/package-macos.sh` that builds a release `Velocity.app`: Info.plist (bundle id
  `dev.velocity.Velocity`, version from Cargo, `NSHighResolutionCapable`, `LSMinimumSystemVersion` 14
  (corrected by the reviewer: the platform layer requires macOS 14 for view-bound `CADisplayLink`),
  **document types** for common text/source extensions with "Editor" role, `NSServices` not needed, appearance
  support), our own app icon (generated by a script from an original design — no Sublime artwork), the bundled
  resources (syntaxes from `third_party/sublime-packages` with their LICENSE, our Default/Theme/Color Scheme
  packages, the spelling dictionary with its license), and a `velocity` CLI launcher inside the bundle
  (`Contents/SharedSupport/bin/velocity`) that forwards to the running instance like Sublime's `subl`.
- Universal binary (arm64 + x86_64) when both targets are installed, otherwise arm64; a `.dmg` with the app
  and an Applications link; **ad-hoc code signing** by default, with optional Developer ID signing and
  notarization when environment variables provide an identity/credentials (document; never commit secrets).
- A "Install Command Line Tool" command (`install_cli`) that symlinks the launcher into `/usr/local/bin` or
  `~/.local/bin` with a confirmation (lane A wires the menu; provide the function and tests).
- GitHub Actions: a `release-artifacts` workflow on tags (`v*`) and manual dispatch that builds the `.app` and
  `.dmg` and uploads them as **workflow artifacts only** — do not create GitHub Releases or publish anything.
- Tests: a script self-test that validates the bundle layout, plist keys, codesign verification (ad-hoc), CLI
  forwarding against a running instance (headless where possible).

## 2. Crash reporting (local only)

- `vel-crash`: panic hook + signal handler (where safe) writing a crash report (version, OS, backtrace,
  last N log lines, no document contents) to `~/Library/Logs/Velocity/`; on next launch the app offers to open
  the report folder (lane A wires the prompt). No network upload.

## 3. Package management core (no Python)

- `vel-packages`: list installed packages (loose `Packages/<name>` and `Installed Packages/*.sublime-package`),
  install a `.sublime-package` from a local file or an HTTPS URL (download to a temp file, verify zip, atomic
  move into `Installed Packages`), remove, disable/enable via `ignored_packages`, upgrade check against an
  optional user-configured JSON index (a minimal schema of our own; empty by default — no bundled index, no
  default network access), report which package resources (syntaxes, color schemes, themes, keymaps, snippets,
  completions, build systems) each package contributes and which ones need Python (plugins `*.py`) — those
  are marked "partially supported: no plugin API" rather than failing.
- Tests with locally generated `.sublime-package` fixtures; the HTTPS path tested against a local test server.
